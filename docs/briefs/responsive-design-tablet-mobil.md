STEP 04 — RESPONSIVE DESIGN, TABLET & MOBILE OPTIMIZATION

IMPORTANT:

The full Najia website UI, page architecture, design system, interactions and animations have already been created.

DO NOT redesign the website.

DO NOT create a new visual identity.

DO NOT change the existing brand direction.

DO NOT remove existing pages or sections.

DO NOT turn the website into a single-page website.

This step is ONLY for responsive optimization and refinement across:

1. Desktop
2. Tablet
3. Mobile

The existing Desktop design is the MASTER visual reference.

==================================================
1. RESPONSIVE PHILOSOPHY
==================================================

The website must be a true responsive MULTI-PAGE website.

Responsive design does NOT mean simply shrinking the Desktop layout.

Each breakpoint should intelligently adapt:

- Layout
- Typography
- Spacing
- Navigation
- Cards
- Images
- Grids
- Interactions
- Animations
- Forms
- Content density

The visual identity must remain exactly the same.

ONE BRAND.
ONE DESIGN SYSTEM.
ONE TYPOGRAPHY SYSTEM.
ONE COLOR SYSTEM.
ONE COMPONENT SYSTEM.

==================================================
2. BREAKPOINTS
==================================================

Optimize the website for:

DESKTOP
Large desktop screens and standard desktop screens.

TABLET
Landscape and portrait tablet sizes.

MOBILE
Small and large mobile screens.

Use responsive layouts rather than fixed dimensions.

Avoid:
- Horizontal overflow
- Broken grids
- Cropped content
- Tiny text
- Overlapping elements
- Buttons that become difficult to tap
- Excessive whitespace
- Extremely compressed sections

==================================================
3. DESKTOP
==================================================

Preserve the current Desktop design.

Do not redesign it.

Verify:

- 12-column grid
- Maximum content width
- Section spacing
- Hero proportions
- Typography hierarchy
- Navigation
- Cards
- Images
- CTA hierarchy
- Footer
- Animations

Make sure the visual hierarchy remains strong on wide screens.

Do not stretch content excessively across very large monitors.

Use appropriate max-width containers.

==================================================
4. TABLET — VERY IMPORTANT
==================================================

Tablet is a PRIMARY responsive target.

Do NOT treat Tablet as a smaller Desktop.

Do NOT simply scale everything down.

Recompose layouts where necessary.

Tablet must have its own intelligent layout behavior.

IMPORTANT:

Tablet remains a MULTI-PAGE WEBSITE.

The navigation does NOT become a scroll navigation.

Example:

Tablet user:
Clicks "المصادر"

→ Navigate to Resources Page.

NOT:

→ Scroll down to the Resources section inside Homepage.

The same applies to:

عن ناجية
المجتمع
المصادر
الفعاليات
الإعلام والتكريم
شارك معنا

==================================================
5. TABLET HEADER
==================================================

Create an optimized Tablet Header.

Possible structure:

Logo
+
Main navigation / compact navigation
+
Primary CTA
+
Menu if required

The Header must remain clean and readable.

Do not squeeze the Desktop navigation until it becomes unreadable.

If the navigation becomes too wide:

Use a compact menu.

Maintain:

- Active page state
- CTA
- Logo
- RTL
- Smooth sticky behavior

==================================================
6. TABLET HERO
==================================================

Recompose the Hero instead of simply shrinking it.

Maintain:

- Strong headline
- Supporting text
- CTA buttons
- Main visual

Use either:

2-column layout

OR

controlled stacked layout

depending on available width.

The headline must remain readable.

Do not allow the Hero image to dominate the text.

Do not make the CTA buttons too small.

Maintain the emotional visual impact.

==================================================
7. TABLET TYPOGRAPHY
==================================================

Use responsive typography.

Do NOT simply use Desktop font sizes.

Maintain hierarchy:

Display
H1
H2
H3
Body
Caption
Buttons

Cairo remains the primary Arabic font.

Maintain RTL.

Headlines should remain strong but never overflow.

Body text must remain comfortable to read.

==================================================
8. TABLET HOMEPAGE SECTIONS
==================================================

Preserve all important Homepage sections.

Do NOT remove sections just because the viewport is smaller.

Homepage must still contain:

Hero
Introduction
Survivorship Journey
Four Pillars
أنا ناجية
Survivor Stories
Najia Creative & Productive
Resources Preview
Events Preview
Impact
Safe Space
Founder
Final CTA
Footer

Recompose layouts intelligently.

Examples:

Desktop:
4-column

Tablet:
2 × 2

Desktop:
3-column cards

Tablet:
2-column cards

Desktop:
large horizontal composition

Tablet:
controlled horizontal scroll or stacked composition

==================================================
9. TABLET FOUR PILLARS
==================================================

Desktop may use a central interactive ecosystem.

Tablet should remain easy to use.

Use:

2 × 2 grid

OR

horizontal interaction

Each pillar must remain readable and tappable.

Interaction should not depend on hover.

Use Tap for Tablet.

==================================================
10. TABLET SURVIVOR STORIES
==================================================

Use:

2-column layout

or

horizontal swipeable stories.

Images should remain large enough.

Text must remain readable.

CTA must remain easy to tap.

Do not reduce cards to tiny thumbnails.

==================================================
11. TABLET RESOURCES
==================================================

Use:

2-column resource layout

with:

Search
Filters
Categories

Keep controls touch-friendly.

Do not place too many filters in one row.

Use a compact filter interaction if needed.

==================================================
12. TABLET EVENTS
==================================================

Use:

Horizontal timeline

or

2-column event layout.

The user should be able to explore event information comfortably.

Do not compress event cards excessively.

==================================================
13. TABLET IMPACT
==================================================

Use:

2 × 2 layout

for the main impact numbers.

Maintain animated counters.

Numbers must remain visually prominent.

==================================================
14. TABLET FORMS
==================================================

Forms should use comfortable field widths.

Avoid:

Tiny fields
Multiple cramped fields in one row
Small buttons

Use:

1–2 columns depending on available width.

Maintain clear labels and validation states.

==================================================
15. MOBILE
==================================================

Mobile should feel intentionally designed.

Do NOT simply stack Desktop elements without considering UX.

Use:

- Single-column layouts
- Clear hierarchy
- Large touch targets
- Simplified navigation
- Swipeable sections where useful
- Shorter text blocks
- Responsive images
- Comfortable spacing

==================================================
16. MOBILE HEADER
==================================================

Use:

Logo
+
Menu button

شارك معنا

Primary CTA:

انضمي إلى المجتمع

Use a clean full-screen or large overlay menu.

Maintain RTL.

==================================================
17. MOBILE HERO
==================================================

Hero should be vertically composed.

Suggested structure:

Logo / visual
↓
Headline
↓
Supporting text
↓
Primary CTA
↓
Secondary CTA

Maintain strong visual impact.

Do not make the headline excessively large.

Do not hide important content.

==================================================
18. MOBILE HOMEPAGE
==================================================

Preserve the complete story but simplify layouts.

Use:

Single-column sections
Swipeable cards
Horizontal content where appropriate
Shorter previews
Clear CTAs

Do not remove major sections.

The Homepage remains the main storytelling experience.

==================================================
19. MOBILE FOUR PILLARS
==================================================

Use:

Swipeable cards

OR

stacked interactive cards.

Each pillar must be:

- Easy to tap
- Easy to read
- Visually distinct
- Consistent

Do not depend on hover.

==================================================
20. MOBILE "أنا ناجية"

Use scroll-based transitions.

Words:

واعية.
مطمئنة.
قادرة.
منتجة.
ملهمة.

Keep animations lightweight.

Avoid heavy parallax on mobile.

==================================================
21. MOBILE STORIES
==================================================

Use:

Horizontal swipe

or

single-column editorial cards.

Images should remain large.

Avoid tiny thumbnails.

CTA must be obvious.

==================================================
22. MOBILE RESOURCES
==================================================

Use:

Search
+

+
Featured resource
+
Resource list

Do not make the filter interface complicated.

==================================================
23. MOBILE EVENTS
==================================================

Use:

Vertical timeline

or

horizontal swipeable event cards.

Maintain event dates and titles clearly.

==================================================
24. MOBILE IMPACT
==================================================

Use:

2 × 2

or

single-column statistics.

Maintain animated counters but keep them lightweight.

==================================================
25. MOBILE FORMS
==================================================

All form fields should be full-width.

Buttons should be large enough for comfortable tapping.

Maintain:

Default
Focus
Error
Success
Disabled

states.

==================================================
26. TOUCH TARGETS
==================================================

All interactive elements must be touch-friendly.

Buttons
Links
Icons
Cards
Filters
Menu controls

Avoid tiny clickable elements.

Maintain comfortable spacing between interactive elements.

==================================================
27. RESPONSIVE IMAGES
==================================================

Images must adapt naturally.

Avoid:

- Distortion
- Important subject cropping
- Unnecessary cropping of faces
- Low-quality images
- Excessive image height on mobile

Maintain consistent image treatment across the design system.

For Saudi women:

Maintain culturally appropriate styling, modest clothing and hijab where appropriate.

==================================================
28. RESPONSIVE ANIMATION
==================================================

Animation intensity must adapt to device.

DESKTOP:

Rich:
- Parallax
- Hover
- Mouse interaction
- Scroll storytelling

TABLET:

Moderate:
- Scroll animation
- Tap interaction
- Reduced hover dependence

MOBILE:

Light:
- Fade
- Slide
- Reveal
- Short transitions
- Swipe

Avoid heavy parallax on mobile.

==================================================
29. PERFORMANCE
==================================================

Responsive animations should feel fast.

Avoid:

- Excessive simultaneous animations
- Large layout shifts
- Heavy effects
- Unnecessary blur
- Long transitions

Content should appear quickly.

Animation should never block the user from reading or navigating.

==================================================
30. RTL
==================================================

The entire responsive website must remain properly RTL.

Check:

Navigation
Text alignment
Icons
Arrows
Breadcrumbs
Forms
Cards
Timelines
Carousels
Menus

Directional icons should also make sense in RTL.

Do not simply mirror everything blindly.

Use culturally and contextually correct directionality.

==================================================
31. MULTI-PAGE RESPONSIVE NAVIGATION
==================================================

This requirement is critical.

Desktop, Tablet and Mobile must all use the same page architecture.

Main pages:

الرئيسية
عن ناجية
المجتمع
المصادر
الفعاليات
الإعلام والتكريم

Primary CTA:

Scrolling is only for content inside the current page.

DO NOT convert the website into a single-page experience at any breakpoint.
